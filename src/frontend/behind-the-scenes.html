一句话总结

这个产品不是用 AI 一句话生成的。我（一个不会写代码的设计专业学生）指挥 Claude Code 当我的工程师团队，通过两次迭代、三轮测试、六项生产环境加固，把一个想法变成了运行在真实服务器上的完整产品。

我做了什么（人的部分）

我的角色不是写代码，而是定义方向和控制质量：

  • 市场调研：搜索南京 AI 岗位需求，分析自己的优劣势，确认「面向设计学生+AI 评审学习工具」的产品方向
  • 目标用户决策：在「专业设计师工具」和「学生学习辅助」之间选择后者，因为核心价值是启发思考
  • 交互流程设计：定义上传→选维度→评审→追问的核心路径
  • 设计原则知识整理：把尼尔森十大原则、格式塔原理等设计理论用于 Prompt 设计
  • Prompt 工程迭代：发现 AI 编造像素值后修改 GLM-4V Prompt，要求用相对描述；发现小数评分被 Pydantic 拒绝后修正数据模型
  • 质量审查：AI 写完代码后检查 CORS 配置、JSON 解析鲁棒性、错误信息安全等
  • 部署运维：配置 Nginx 路由、systemd 服务、测试 AI 管道端到端

关键设计决策

为什么用双模型管道而不是一个多模态模型？

GLM-4V 擅长客观视觉识别，DeepSeek 擅长中文推理和教学式表达。分开让「看设计」和「评设计」各司其职，Prompt 更可控，成本也低（每次约 0.03 元）。

为什么前端不用 React/Vue？

交互不复杂，纯 HTML/CSS/JS 对 Claude Code 最友好，修改零成本。用框架反而增加 AI 协作负担。

为什么 Prompt 强调「引导式」而非「说教式」？

目标用户是学习中的设计学生。冰冷的技术评审让人沮丧，启发式反馈让人愿意继续学。给 AI 设定了「用生活类比」「不说你应该这样做」的语调约束。

核心收获

不会写代码不是做不出产品的理由。在 AI 时代，知道自己要做什么产品比知道怎么写代码更重要。竞争力不是技术栈的熟练度，而是产品判断力 + AI 协作能力。
