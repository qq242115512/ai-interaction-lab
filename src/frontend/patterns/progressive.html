Pattern 07

渐进式加载

按认知顺序分步展开，降低信息过载

Design Rationale

解决的问题：复杂信息一次性展示会导致认知过载。6 个维度、每个 3-4 条发现、每条关联设计原则——这个信息量足以让任何人放弃阅读。引用米勒定律（7+/-2）和Hick 定律（希克定律）——选项越多决策越慢。

设计决策：SSE（Server-Sent Events）分阶段推送状态更新——视觉分析、流式生成、解析整理、完成。每阶段有独立的图标和文字，符合渐进式信息披露（Progressive Disclosure）原则。同时满足Doherty Threshold（多尔蒂阈值）——系统响应时间小于 400ms 时，用户保持心流状态，不会切换注意力。

生活类比：新闻的标题、导语、正文结构。你可以只看标题了解发生了什么，也可以深读正文了解细节。没有人强迫你一开始就读全文。好的渐进式加载让用户自己控制深入程度——就像爬楼梯，每一步都有新的发现。

How It Works
1

SSE 推送阶段事件

后端通过 SSE 推送 step: visual 事件，前端收到后点亮第 1 张卡片，显示"GLM-4V 正在分析设计元素..."。用户立即知道系统在工作。

2

逐 token 流式推送 + 阶段过渡

visual_done 事件完成第 1 步并开启第 2 步。随后 chunk 事件逐 token 推送评审文本，用户看到文字实时生成——满足 Doherty Threshold 的 < 400ms 响应要求。

3

done 事件触发全部完成

最后一个 done 事件标记所有步骤完成，前端展示完整的维度摘要和发现列表。用户经历了"分析→生成→整理"的完整认知旅程。

async def stream_review_with_steps(visual: str, dims: list):
    """SSE with progressive step events."""
    yield f"data: {json.dumps({'step': 'visual',
        'message': '正在识别设计元素...'})}\n\n"
    await asyncio.sleep(0.1)

    visual_result = await glm_analyze_image(visual)
    yield f"data: {json.dumps({'step': 'visual_done',
        'message': '视觉分析完成'})}\n\n"

    client = deepseek_client()
    response = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user",
            "content": build_prompt(visual_result, dims)}],
        stream=True
    )

    full_text = ""
    for chunk in response:
        if chunk.choices[0].delta.content:
            text = chunk.choices[0].delta.content
            full_text += text
            yield f"data: {json.dumps({'event': 'chunk',
                'text': text})}\n\n"

    result = parse_json_response(full_text)
    yield f"data: {json.dumps({'event': 'done',
        **result})}\n\n"
